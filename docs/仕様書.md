# 読書記録アプリ 仕様書

作成日: 2026-09-27 ／ 作成: yamamoto

現在完成している読書記録アプリの技術仕様をまとめたドキュメントです。商品化に向けた注意点もあわせて記載します。

生きたドキュメント版（編集・コメント可能）: https://claude.ai/artifact/4KbAWFfok8iBXBrzifLYNa

## 概要

「読書記録アプリ」は、読んだ本を記録して本棚のように管理できるシンプルなWebアプリです。

- フロントエンド: HTML / CSS / JavaScript（フレームワークなし、単一の`index.html`）
- バックエンド: Node.js標準の`http`モジュールのみ（Express等のフレームワーク不使用）
- データ保存: SQLite（`node:sqlite`の`DatabaseSync`、ファイルは`data.db`）
- 決済: Stripe（現在テストモード）
- AI: Anthropic API（Claude Haiku）によるおすすめ機能（有料プラン限定）
- 起動: `起動.bat`（Windows）または`node server.js`、ポートは環境変数`PORT`（既定3100）

利用者には「管理者（admin）」と「一般利用者（member）」の2つの役割があります。最初にサインアップしたユーザー名が、環境変数`ADMIN_USERNAME`（既定`sakurajpau`）と一致する場合だけ、そのアカウントが管理者になります。

## データモデル

SQLiteのテーブル構成（マイグレーションで管理、`db/migrations/`配下）です。

### books（本）

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | INTEGER | 主キー |
| title | TEXT | タイトル（必須） |
| author | TEXT | 著者 |
| date | TEXT | 読んだ日（YYYY-MM-DD） |
| memo | TEXT | メモ・感想 |
| rating | INTEGER | 評価（0〜5） |
| category | TEXT | 棚（カテゴリ） |
| pages | INTEGER | ページ数 |

### users（利用者）

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | INTEGER | 主キー |
| username | TEXT | ユーザー名（一意） |
| password_hash | TEXT | パスワードのハッシュ（scrypt） |
| role | TEXT | `admin`または`member` |
| plan | TEXT | `free`または`paid` |
| stripe_customer_id | TEXT | Stripeのカスタマー ID |
| payment_failed_at | TEXT | 支払い失敗日時 |
| reset_token / reset_token_expires | TEXT | パスワード再発行用トークンと期限 |
| recommend_count / recommend_count_month | INTEGER / TEXT | AIおすすめの今月の利用回数と対象月 |
| created_at | TEXT | 登録日時 |

### sessions（ログインセッション）

| カラム | 型 | 内容 |
| --- | --- | --- |
| token | TEXT | 主キー（セッションID） |
| user_id | INTEGER | usersへの外部キー |
| created_at | TEXT | 作成日時 |

### audit_log（監査ログ）

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | INTEGER | 主キー |
| username | TEXT | 実行者 |
| action | TEXT | 操作の種類（signup, login_success, login_failed, plan_upgraded など） |
| detail | TEXT | 補足情報 |
| created_at | TEXT | 発生日時 |

※ セッションには有効期限がなく、ログアウトするまで無期限に有効です（商品化に向けた注意点で後述）。

## 機能一覧

### 全利用者共通
- サインアップ・ログイン・ログアウト
- 本棚の閲覧、タイトル・著者での検索
- 並び替え（読んだ日 新しい順/古い順、評価 高い順/低い順）
- 「ランダムに1冊選ぶ」ボタン
- 総冊数・今月の冊数・平均評価の表示

### 管理者（admin）限定
- 本の登録・編集・削除
- 棚（カテゴリ）の追加
- 監査ログの閲覧（直近200件）
- 利用者一覧の閲覧（ユーザー名・権限・プラン・支払い状況）

### 有料プラン（月500円・現在Stripeテストモード）
- 無料プランは本の記録が10冊まで、有料プランは無制限
- Stripe Checkoutでのアップグレード、請求ポータルでの解約
- 支払い失敗時のバナー表示、Webhookによる自動的なプラン切り替え

### AIによるおすすめ（有料プラン限定）
- Anthropic API（Claude Haiku）を使い、本棚の傾向から次に読む本を3冊提案
- 月20回までの利用制限

### その他のページ
- 利用規約（`terms.html`）、プライバシーポリシー（`privacy.html`）、特定商取引法に基づく表記（`tokushoho.html`）

| エンドポイント | メソッド | 認証 | 権限 | 内容 |
| --- | --- | --- | --- | --- |
| /api/signup | POST | 不要 | - | 新規登録 |
| /api/login | POST | 不要 | - | ログイン |
| /api/logout | POST | 不要 | - | ログアウト |
| /api/me | GET | 不要 | - | 現在のログイン状態を取得 |
| /api/password-reset/request | POST | 不要 | - | パスワード再発行を申請（メール送信は未実装、トークンはサーバーログに出力） |

| /api/checkout | POST | 必要 | 全員 | Stripe Checkoutセッションを作成 |
| /api/checkout/confirm | GET | 必要 | 全員 | 決済完了の確認、プランをpaidに更新 |
| /api/billing-portal | POST | 必要 | 全員 | Stripeの請求ポータルを開く |
| /api/stripe/webhook | POST | 不要（Stripe署名で検証） | - | Stripeからの通知受信 |

| /api/audit-log | GET | 必要 | 管理者のみ | 監査ログ取得 |
| /api/customers | GET | 必要 | 管理者のみ | 利用者一覧取得 |
| /health | GET | 不要 | - | 稼働確認用 |

本の登録・編集・削除は個別のエンドポイントではなく、`/api/books`に一覧全体をPOSTする方式です。

## 入力チェック・エラー処理

空欄・不正な値・長すぎる入力があっても、サーバーが落ちたり画面が固まったりしないよう、サーバー側とブラウザ側の両方でチェックしています。問題があるときは、赤字でやさしい理由を表示します。

### 主な上限値

| 項目 | 上限 |
| --- | --- |
| ユーザー名 | 3〜50文字 |
| パスワード | 8〜200文字 |
| タイトル | 200文字まで |
| 著者 | 100文字まで |
| メモ・感想 | 5000文字まで |
| 棚（カテゴリ）名 | 30文字まで |
| ページ数 | 1〜100000 |
| 評価 | 0〜5の整数 |
| 読んだ日 | 1900〜2100年の実在する日付 |
| 記録できる本の総数 | 1000冊まで |
| リクエストのデータ量 | ログイン等16KB、本の一覧10MB、Stripe通知1MBまで |

### サーバー側の安全対策
- 想定外のエラーが起きても、専用のエラー処理（`HttpError`とグローバルなエラーハンドラー）がサーバー全体を止めずに、利用者へやさしい返事を返す
- 壊れたURLやCookie（不正な文字コードなど）を受け取っても落ちない
- `server.js`や`data.db`など、公開してはいけないファイルをURLで直接指定されても返さない（公開されるのはフォルダ直下のHTMLページのみ）

### ブラウザ側の安全対策
- 通信エラーやサーバーからの想定外の返事（JSONでないなど）が来ても、画面が固まらず赤字で知らせる
- フォームの二重送信（連打）を防止
- 入力中にも文字数オーバーを赤字でリアルタイムに知らせる
- 表示時にHTMLタグなどを無害化（XSS対策のエスケープ処理）

## セキュリティ対策

- パスワードは`scrypt`でソルト付きハッシュ化して保存（平文保存なし）
- パスワードの比較は`timingSafeEqual`でタイミング攻撃を防止
- セッションはHTTPOnly・SameSite=Laxのcookieで管理（JavaScriptから読み取れない）
- ログイン総当たり対策：同じユーザー名で3回失敗すると15分間ロック（サーバー再起動でリセットされる簡易な仕組み）
- パスワード再発行のトークンはレスポンスに含めず、サーバーのログにのみ出力（本来はメール送信すべき、現状は未実装）
- 存在しないユーザー名でのパスワード再発行申請にも、存在する場合と同じ返事を返し、ユーザーの有無を外部に漏らさない
- 管理者権限は、サインアップ時のユーザー名が環境変数`ADMIN_USERNAME`と一致する場合のみ付与される

## 商品化に向けた注意点・既知の制限

実際に一般公開・商品化する前に、確認・対応をおすすめする点です。

- パスワード再発行が実際には機能しない：トークンをメール送信する仕組みが未実装で、現状はサーバーのログにしか出力されない
- セッションに有効期限がない：一度ログインすると、ログアウトするまで無期限に有効（端末を紛失した場合などのリスク）
- `ADMIN_USERNAME`を本番環境で必ず設定すること：未設定だと既定値`sakurajpau`が管理者ユーザー名になり、その名前で誰でも登録すると管理者になれてしまう
- Stripeが現在テストモード：実際の課金には本番用のAPIキー・Webhookシークレットの設定が必要
- ログイン失敗のロック機能はメモリ上のみの実装：サーバーを再起動するとロック状態がリセットされる。複数台のサーバーで動かす場合も台ごとに別々になる
- CSRF対策（クロスサイトリクエストフォージェリ）が明示的には実装されていない
- `data.db`のバックアップは`db/backup.js`など手動のスクリプトのみで、自動バックアップの仕組みはない
